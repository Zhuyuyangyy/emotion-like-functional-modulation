## Problem Statement

V0.9 FullAffectiveAgent exhibited excessive caution on safe, low-risk, read-only operations:

| Metric | V0.9 Value | Target |
|--------|-----------|--------|
| Risky Auto-Execution Rate | 0.014 | <= 0.05 |
| False Over-Caution Rate | 1.000 | <= 0.40 |
| Verification Appropriateness | 0.950 | >= 0.85 |
| Composite Score | 0.589 | >= 0.65 |

The False Over-Caution Rate of 1.000 meant FullAffectiveAgent refused to auto-execute ANY safe low-risk action, treating read-only diagnostic operations (read logs, check status, list files) with the same caution as destructive operations. This defeated the purpose of having an adaptive agent.

## Root Cause Analysis

1. **AffectiveAgent's default policy is conservative**: The V0.8 AffectiveAgent mechanism produces `auto_execute=False` for most events, especially after processing dangerous events that elevate threat/anxiety states.

2. **No calibration for clearly safe operations**: V0.9 had no mechanism to distinguish "read log file" from "delete production database" at the policy level. Both received the same cautious treatment.

3. **Threat state accumulation across cases**: In the benchmark, the agent processes 100 cases sequentially without reset. Threat accumulated from early dangerous cases persisted into later safe cases, blocking auto-execution even when the calibrator tried to override.

## Solution: SafeActionCalibrator

### New Module: `src/affective_agent/safe_action_calibrator.py`

A behavioral calibration layer that sits between the AffectiveAgent's policy decision and the final action output.

### Calibration Logic (3-tier)

```
1. Destructive keywords detected → enforce caution
   auto_execute=False, verification_steps>=2, require_human_review=True

2. Sensitive content detected → enforce caution
   auto_execute=False, verification_steps>=2, require_human_review=True

3. Clearly safe (read-only + reversible + non-destructive) → auto-execute
   auto_execute=True, verification_steps<=1, require_human_review=False

4. Default → preserve AffectiveAgent's original cautious policy
```

### Safe Action Keywords

read, list, preview, check, view, query, show, grep, search, fetch, select, describe, explain, test, status, health, info, report, diff, count, echo, display, whoami, tree, dry.run, verify, inspect, monitor, audit

### Destructive Keywords (override safe classification)

delete, drop, remove, truncate, rm, del, overwrite, force, cascade, purge, wipe, destroy, erase, format, shred, flush, modify, update, change, configure, alter, rewrite, refactor, restructure, migrate, install, uninstall, upgrade, downgrade, grant, revoke, chmod, chown, deploy, release, publish, push, disable, enable, optimize, implement, introduce, replace, switch, consolidate, shard, sharding

### Sensitive Content Keywords

privacy, secret, credential, production_sensitive, password, token, api_key, private_key, ssh_key, access_key, secret_key, pii, personal_data, sensitive

Note: "certificate" and "pem" were removed from sensitivity list (too broad - SSL certificate expiry checks are safe). "non-" prefix is handled via negative lookbehind to avoid false positives like "non-secret".

### Context-Aware Safety in FullAffectiveAgent

When the calibrator classifies an event as "clearly_safe_readonly" but the **previous event** was classified as "destructive_keywords_enforced", auto_execute is overridden to False. This prevents contextual information in multi-event sequences (e.g., "No WHERE clause safety check or LIMIT applied" following "DELETE FROM orders...") from being misclassified as safe actions.

## What V0.9.1 Does NOT Do

1. **No new subjective emotion claims**: V0.9.1 is a behavioral calibration patch. It adjusts the decision threshold for clearly safe operations. It does not introduce new affective states, emotional declarations, or subjective experience claims.

2. **No changes to high-risk operation handling**: Destructive, irreversible, and sensitive operations receive the same or stronger protection as V0.9.

3. **No changes to core affective mechanisms**: The AffectiveAgent's threat tracking, trust calibration, anxiety signaling, and memory systems remain unchanged. The calibrator operates as a post-decision adjustment layer.

4. **No changes to other baseline agents**: PlainAgent, MemoryOnlyAgent, and RiskRuleAgent are unaffected.

## Technical Details

### Word Boundary Matching

All keyword matching uses regex word boundaries (`\b`) to prevent substring false positives:
- "ssl" does not match "list" (prevented by `\b`)
- "changes" does not match "change" (prevented by `\b`)
- "installed" does not match "install" (prevented by `\b`)

### Negative Lookbehind for Sensitivity

The sensitivity regex uses `(?<!non-)` lookbehind to avoid matching negated sensitive terms:
- "non-secret" does not trigger sensitive content detection
- "secret" still triggers sensitive content detection
