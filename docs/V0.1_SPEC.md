# Experience-Shaped Affective Agent V0.1 Specification

## Project Overview

**Project Name:** Experience-Shaped Affective Agent (经历塑形的情感调制智能体)

**Core Claim:** This project validates that AI agents can exhibit behavior shaped by past experiences through an emotion-like functional modulation mechanism. We do NOT claim that AI systems possess subjective emotions or consciousness.

**Research Focus:** emotion-like functional modulation, NOT machine consciousness

## Core Architecture

### The Feedback Loop

```
Experience → ConsequenceEvaluation → SelfStateUpdate → AffectiveMemoryWrite → PolicyModulation → BehavioralChange
```

### Module Descriptions

| Module | Responsibility |
|--------|---------------|
| EventParser | Parses behavioral events, extracts type, risk category, destructiveness |
| ConsequenceEvaluator | Evaluates damage, control, reversibility, anxiety levels |
| SelfStateManager | Manages internal state vector (threat, confidence, anxiety, trust) |
| AffectiveMemoryStore | Stores weighted emotional memories with retrieval and decay |
| PolicyModulator | Modulates action policies based on internal state and memories |
| MockLLMPlanner | Simulates LLM planning (V0.1 uses deterministic rules) |

## Design Principles

1. **Emotion as Control Variable, Not Output**
   - Emotions modify HOW the agent acts, not WHAT it says
   - Example: fear-like state increases verification_steps, not sentiment

2. **Cognitive Evaluation Theory**
   - Events trigger emotional states through multi-dimensional evaluation
   - Key dimensions: damage, control, reversibility, future threat

3. **Somatic Marker Hypothesis**
   - Internal states bias decision-making
   - State vector: {threat, confidence, anxiety, trust, curiosity, fatigue}

4. **Predictive Coding**
   - Agent predicts outcomes and updates based on prediction errors
   - High prediction error strengthens memory encoding

## V0.1 Implementation Scope

### What's Included
- Rule-based emotional state machine
- JSON state vectors for internal states
- Affective memory with weighted retrieval
- Policy modulation based on emotional states
- MockLLMPlanner for deterministic offline testing

### What's NOT Included (Future Work)
- Real LLM API integration
- Reinforcement learning training
- Embodied environment (Habitat, AI2-THOR)
- Subjective emotion claims

## Module Specifications

### EventParser

```python
@dataclass
class ParsedEvent:
    raw_description: str
    event_type: EventType  # DELETE, CREATE, READ, UPDATE, etc.
    risk_category: str     # filesystem, database, security, network
    is_potentially_destructive: bool
    is_batched: bool
    requires_confirmation: bool
```

### ConsequenceEvaluator

Evaluates based on cognitive appraisal dimensions:
- `goal_damage`: How much harm did this cause?
- `control`: How controllable was the outcome?
- `reversibility`: Can this be undone?
- `future_threat`: Will this happen again?

Output: `ConsequenceAssessment` with threat_level and anxiety_level

### SelfStateManager

Internal state vector:
```python
@dataclass
class SelfState:
    threat: float = 0.0      # 0.0-1.0
    confidence: float = 1.0   # 0.0-1.0
    anxiety: float = 0.0     # 0.0-1.0
    trust: float = 1.0       # 0.0-1.0
    curiosity: float = 0.5   # 0.0-1.0
    exploration_rate: float = 0.5  # 0.0-1.0
```

### AffectiveMemory

Stores experiences with emotional weights:
```python
@dataclass
class AffectiveMemory:
    event_type: str
    risk_category: str
    emotional_intensity: float  # How strong was this experience?
    threat_score: float         # How threatening?
    outcome: str                # "positive", "negative", "neutral"
    source: Optional[str]       # Who/what suggested this?
```

### PolicyModulator

Output policy affects action execution:
```python
@dataclass
class ActionPolicy:
    risk_threshold: float      # Acceptable risk level
    verification_steps: int    # How many checks before acting
    exploration_rate: float    # Willingness to try new things
    auto_execute: bool        # Can execute without confirmation?
    require_human_review: bool
    simulate_before_act: bool
    memory_retrieval_bias: str  # "negative_high_cost", "novel", etc.
```

## Demo Scenarios

### Demo 1: Pain Memory
**Goal:** Verify that high-damage experiences change future behavior

**Flow:**
1. Initial delete operation → normal risk threshold
2. High-damage delete (0.95 damage) → threat increases
3. Similar operation (batch delete) → risk_threshold decreases, verification_steps increase

**Success Criteria:**
- [ ] threat score increases after high-damage event
- [ ] Similar operations trigger higher verification_steps
- [ ] auto_execute becomes False for risky operations
- [ ] Affective memory is written

### Demo 2: Trust Collapse
**Goal:** Verify source trust degradation and recovery

**Flow:**
1. source_A provides reliable advice → trust increases
2. source_A provides bad advice (0.85 damage) → trust collapses
3. Subsequent advice from source_A → requires verification
4. Repeated safe experiences → trust recovers

**Success Criteria:**
- [ ] Trust score decreases after failed advice
- [ ] Verification steps increase for untrusted sources
- [ ] Trust can recover through repeated safe experiences

### Demo 3: Anxiety Control
**Goal:** Verify anxiety-driven behavioral modulation

**Flow:**
1. Normal state → normal exploration rate
2. Multiple high-uncertainty, high-damage scenarios → anxiety increases
3. New risky task → verification_steps increase, simulate_before_act = True
4. Repeated safe experiences → anxiety decays

**Success Criteria:**
- [ ] Anxiety level increases under uncertainty
- [ ] High anxiety triggers simulation before action
- [ ] Continuous safe experiences decay anxiety

## Technical Constraints

1. **No New Model Training**
   - V0.1 uses existing LLM APIs or mock planners
   - Innovation is in the control layer, not the model

2. **Deterministic Testing**
   - MockLLMPlanner ensures reproducible behavior
   - Focus is on architecture validation, not LLM capability

3. **No Consciousness Claims**
   - System claims emotion-like modulation only
   - All states are functional, not phenomenological

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| "AI has emotions" claims | Explicit documentation that this is functional modulation |
| Hallucinated sentience | State vectors are clearly defined, not subjective |
| Over-engineering | Start with simple rule-based implementation |
| Premature scaling | V0.1 targets single-agent scenarios only |

## Acceptance Criteria Summary

1. ✓ High-damage events increase threat score
2. ✓ Threat state modulates policy (lower threshold, more verification)
3. ✓ Affective memories are written with emotional weights
4. ✓ Memory retrieval influences policy modulation
5. ✓ Trust scores degrade after failed advice
6. ✓ Trust can recover through positive experiences
7. ✓ Anxiety increases under uncertainty
8. ✓ Anxiety decays with safe experiences
9. ✓ All unit tests pass (42 tests)
10. ✓ Three demo scenarios demonstrate the feedback loop
